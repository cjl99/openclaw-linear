# 启动恢复

服务完成本机状态初始化后立即返回，不在启动阶段等待旧任务。后台通过
Gateway `health` RPC 确认就绪，再启动任务 worker 和旧 run 恢复；就绪前收到
的 webhook 仍可持久化入队。

只有服务启动时捕获的绑定属于恢复候选。这些 Session 在 worker 启动前保持
blocked；Gateway 就绪后，其他 Session 可以正常处理。

恢复最多四路并发，每轮总预算 30 秒，取消请求和结束状态观察分别限制为
两秒。只有针对同一 run 的明确取消响应或结束状态才能确认恢复；查不到 run
或请求失败不代表任务已停止。写入前再次核对 active 的 run ID 和 session key，
避免旧恢复结果清理新任务。

确认成功后移除旧绑定、解除对应 Session 的阻塞。未确认则保留阻塞，
`recovery:<sessionId>` 保存尝试次数、状态和下次尝试时间；重试从五分钟逐步
退避到一小时，重启后也保留退避时间。后台每分钟检查到期重试；耗尽本轮
预算后先暂停五分钟。

服务停止时先中止就绪探测和后台等待，再关闭数据库。不支持取消 waiter 的
宿主 API 可能稍后结束，但不能在恢复停止后继续更新状态。

源码修改需要重新构建并完整重启 Gateway 才能应用。不能仅因实时注册表中
查不到旧 run 就删除 active；未确认的运行应保留状态继续核查。
