# 精简上下文

[English](context.md) | 简体中文

**用户本轮原话始终在最前面。** 首轮优先采用结构化触发评论，否则提取平台 user-request 或主指令评论；不再将整份 Issue、父 Issue、评论 XML 当作用户请求。无法识别原话时要求 Agent 用官方 Linear MCP 读取原始请求，不猜测任务。

后面只保留短标题（最多 120 字符）、去掉 slug 的 Issue URL（最多 180 字符）、变化后的指导摘录（最多 240 字符）。不注入正文、父 Issue、评论树、关系或任意 guidance 对象；完整 Issue 和评论须用官方 MCP 按需读取。普通追问只保留作者署名和原话，复用原生历史，不重复参考背景。

真正的用户请求超过 6,000 字符时，完整原话保存到私有文件，消息只展示前 4,000 和后 1,000 字符，并要求执行前读完整原文；丢弃的 Issue 快照不会再伪装成用户请求。宿主历史丢失时，从不可变 Agent Activities 恢复，当前请求仍在最前，只补最近两条有效用户/回复/追问/错误摘录，每条最多 160 字符；不注入 thought/action 或重复当前 activity。恢复扫描仍受 100 页/100,000 字符安全预算和明确分页错误约束。HTTP 包体上限仍为 1 MiB。

旧会话记录不删除；要避开以前已经塞入的快照，应新建 Agent Session。本插件不增加替代业务 CRUD 工具。

## 消息格式与实例指令

首轮先展示 webhook 当轮作者与规范 Issue 链接，再用独立代码块放用户原话；作者缺失或为自动化时显示 Linear。原话之后才是可点击的短标题、MCP 提示和有界 guidance/历史。代码块分隔符会避开原话中的反引号，防止引用内容越出代码块。

可选 `sessionInstructions` 是受信实例配置字符串，最多 1000 字符；宿主仅在首轮或历史丢失恢复时于末尾追加 `Prompt: ...`，普通追问不重复，webhook 不能设置。需要无法处理时的接管通知，应明确配置目标；普通回复仍由集成投递。本字段不构成超出实例 owner 指令的任意外联授权。

正常追问且宿主历史存在时，只发送 `作者 says:` 和代码块中的本轮原话，不重复链接、标题、MCP 提示和 sessionInstructions。首轮保留完整精简格式；宿主历史丢失时恢复有界引用与实例指令。指导规则有变化或清空时仍仅通知一次。
